# Реализация обновления TAKTO.

## Архитектура

Сохранены React 19, Vite, React Router, Onest, GSAP, текущие стили, Hero, материалы, блок о студии, процесс заказа, FAQ, контакты и информационные страницы. Главная дополнена динамической подборкой, пятью наборами и TAKTO. BUSINESS. Карточки наборов используют собственные векторные мокапы, обозначенные как визуальная концепция.

`CatalogProvider` загружает категории/опубликованные товары из Supabase с серверной пагинацией. `DynamicCatalog` отвечает за поиск, фильтрацию, сортировку и избранное. `/product/:slug` показывает галерею и собирает запрос с ID/SKU, вариантами и количеством. Slug постоянный: изменение названия не меняет адрес.

`/admin` проверяет Supabase Auth и серверную роль. Таблица роли недоступна клиенту; RLS защищает каждую операцию, включая прямые запросы вне интерфейса. Сохранение карточки и галереи атомарное, с проверкой `updated_at` против потери одновременных изменений. Storage закрытый, изображения выдаются по короткоживущим ссылкам только для опубликованных товаров. Старые карточки не публикуются автоматически.

Корзина поддерживает «По запросу», корректные единицы и актуализацию цен опубликованных товаров. Выбранные параметры сохраняются в позиции; снятые с публикации товары блокируют оформление. Старый калькулятор и его демонстрационные тарифы сохранены без новых выдуманных формул. Для динамических карточек используется «Запросить расчёт».

Готовые наборы и тарифы хранятся отдельно в конфигурации, а не в таблице товаров. Их CTA используют существующую форму заявки с точным составом/тарифом/сроком. Telegram настроен на заданный владельцем `@takto_order`.

## Проверки и границы результата

- TypeScript и production-сборка успешно выполнены. `npm test`: 22 проверки пройдены, 0 ошибок; `git diff --check` пройден.
- SQL-миграция выполняется в PostgreSQL через PGlite; сценарии проверяют RLS на уровне запросов для `anon`, `authenticated` без роли и владельца. Служебные схемы Auth/Storage в этом тесте минимально воспроизведены, сам SQL каталога исполняется без подмены.
- Проверены черновик → публикация → редактирование → смена обложки/порядка → скрытие → удаление, атомарный откат при ошибке фото, конфликт версий, неизменность slug, запрет самоназначения администратора и нулевых цен.
- Проверены выборка карусели, форматирование цены, параметры заявки, коммерческая конфигурация; сохранены и выполнены 7 существующих тестов калькулятора/контактов.
- Hosted API проверен публичным ключом: проект отвечает, но миграция ещё отсутствует (`PGRST205`/`PGRST202`). Успешный вход реального владельца и реальная загрузка файлов не подтверждены.
- Визуальная проверка не завершена: встроенный браузер недоступен, подключение к Chrome завершилось тайм-аутом разрешения. Адаптивные правила реализованы, но не выдаются за проверенные скриншотами.
- Production на `takto.uz` не обновлялся. Для запуска нужны применение миграции, настройка hosted Auth, создание владельца, переменные Cloudflare и проверки Preview из инструкции.

## Что осталось для запуска

1. Применить миграцию к выбранному Supabase (вручную или через подключение управления Supabase).
2. Отключить публичную регистрацию, проверить лимиты Auth; создать аккаунт владельца с его email/паролем и записать UUID в `private.catalog_admin`.
3. Указать публичные переменные в существующем Cloudflare Pages, собрать Preview и выполнить проверки реального Auth/Storage и интерфейса.
4. Подтвердить коммерческие условия наборов; проверить отправку посетителем подготовленной заявки в Telegram.
5. Развернуть проверенную ветку через существующий Cloudflare Pages. Новые товары после этого не потребуют деплоев.
